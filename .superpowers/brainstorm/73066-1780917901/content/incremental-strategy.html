增量爬取策略选择

决定每次爬取如何只同步变化的数据，而非全量拉取

当前方式 vs 增量方式

❌ 当前：全量拉取
每次触发 → 登录平台 → 从第1页开始分页 →
遍历全部N页 → 内存去重 → 逐条UPSERT

站点爬取: 全量域名列表（可能上千页）
订单爬取: 全时间范围分页
问题: 90% 的数据没有变化，浪费带宽和时间
✅ 目标：增量同步
定时触发 → 读取上次游标/时间 →
仅拉取变更数据 → 批量 UPSERT

站点: 按 updated_at 拉取变更的域名
订单: 按上次最大 order_id 或时间增量
预期: 每次只处理 ~5-10% 的数据量

选择增量策略

A

定时轮询 — Cron 增量窗口

Spring Boot 内置 Quartz/XXL-Job 定时触发，每次爬取「上次成功截止时间 → 当前时间」窗口内的增量数据。适用于站点和订单数据。简单可靠，但最小间隔受限于一轮爬取耗时。

B

游标增量 — 基于 ID/时间戳

记录上次成功抓取的最大 ID 或 updated_at，下次从该游标续抓。比时间窗口更精确（不漏不重），但需要外部 API 支持按游标排序分页。

C

混合策略 — 按数据源选择

站点爬取用时间窗口（数据变化慢），订单爬取用游标（数据增长快、不可漏单）。每种数据源选择最合适的增量机制。
