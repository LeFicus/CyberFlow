Scrapy 商品爬虫如何融入新架构？

当前 Scrapy 手动运行（python shopify站点.py），需要纳入统一调度吗？

当前状态：Scrapy 完全游离
$ cd crawler-service/app/crawler/ecommerce_spider
$ python shopify站点.py      # 手动 Shopify 商品
$ python 非shopify站点.py      # 手动 WooCommerce 商品

❌ 无调度 · ❌ 无任务状态 · ❌ 无失败重试 · ❌ 无前端触发入口

集成方案

A

完全融入消息队列体系

Spring Boot 下发商品爬取任务到 MQ，Python Scrapy Consumer 消费任务后以子进程方式启动 Scrapy Spider。完成后回写结果状态。前端可统一触发和监控。

改造量：中等 — 需封装 Scrapy 启动脚本，将 Spider 包装为可被消息触发的执行单元
B

定时调度，独立通道

Spring Boot 用 Quartz 定时触发（如每天凌晨 2 点），不走消息队列。通过 HTTP/gRPC 调用 Python 微服务直接执行 Scrapy。商品爬取不需要实时性，定时批量即可。

改造量：较小 — 新增 Python 端点 + Spring Boot 定时 Job
C

暂不集成，保持手动

聚焦站点 + 订单的增量优化。Scrapy 商品爬取保持独立，后续再议。先解决核心数据流的实时性和效率问题。

改造量：无 — 本次不涉及
